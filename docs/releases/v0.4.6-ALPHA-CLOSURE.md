### IR-11 — chat detail pagination safety

| Item | Change |
|---|---|
| **IR-11A** Conversation state isolation | `chatConversationId` resets `chatEntries`/`chatCursor`/`chatHasMore`/`chatPageSize`/`chatLoading` on switch; A→B→A leaks nothing |
| **IR-11B** Cursor ordering | full `(received_at, id)` keyset cursor, not `received_at` alone |
| **IR-11C** Async fetch/render separation | SQLite + AES on the IO executor; `renderChatPage()` UI-thread only |
| **IR-11D** Corrective patch | `chatRequestGen` invalidates stale callbacks; a stale generation cannot clear the newer request's `chatLoading`; `refreshChat()` is render-only (photo return / delete never advance the cursor); lock/`onStop` invalidate in-flight work; delete failure reported honestly |

`photoPreviewReturnPreservesHistory`, `deleteMessageShowsCorrectCount`,
`pagination350and650`, `switchConversationDuringAsyncLoad`,
`dbQueryFailureDoesNotLeakOtherConversation`, `photoReturnPreservesHistoryAndCursor`,
`deleteRemovesMessageFromChatPage`, `staleCallbackDoesNotClearNewRequestLoading`,
`lockRejectsInFlightChatCallback`.
