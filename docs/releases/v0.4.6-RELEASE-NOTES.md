## Read this before installing

### This is a Debug build, not a production release

- **Signed with a Debug certificate.** There is **no release keystore** in this
  project.
- **`android:debuggable=true`.** Anyone with physical access, or with USB
  debugging enabled, can read this app's private files via `adb` / `run-as`.
  **Do not store sensitive information in this build.**
- It is labelled *Experimental* because the real-world validation described
  under "Validation scope" has not been completed.

### Updating later will cost you your data

Android ties an app's update identity to its signing certificate. When this
project eventually ships a **production-signed** build, that build has a
**different certificate**, and Android will refuse to install it over this one.

The only path will be:

```
uninstall  →  all archived notifications are permanently lost  →  install
```

There is **no in-place upgrade** from this Debug Alpha to a production build.
If you want to keep the data, plan for the DHC export below — and read its
limitation first.

## What this app does

An offline, privacy-first Android notification archiver. It stores copies of
messaging notifications (LINE, Telegram, WhatsApp, Instagram, Messenger,
Threads) locally, encrypted, so a message later retracted in the source app can
still be read.

It is **not** a chat client, **not** a relay, and **not** a chat-history backup
tool. It reads only what Android's notification system delivers.

- **No `INTERNET` permission.** Verified absent on the shipped APK.
- No tracking, analytics, or advertising SDKs.
- `FLAG_SECURE` is set unconditionally — screenshots and screen recording are
  blocked.

---

## Data export — one-way only

The app can export an **encrypted DHC archive** (Settings → export).

**There is no in-app restore.** Nothing in this app can read that archive back.
Do not treat the export as a backup you can restore from — at present it is a
one-way export whose only current value is that the bytes exist and are
encrypted.

## Validation scope — what has and has not been tested

**Tested:**

- 290/290 instrumentation tests on an Android emulator (API 36), plus the
  full JVM suite, Lint, and the security / release / test-isolation audits.
- In-place upgrade from the public **v0.4.4-alpha** (same signing certificate)
  on an isolated **API 33** emulator: versionCode 10 → 11, package signature
  unchanged, app data and preferences preserved, and a previously stored
  **encrypted** message was decrypted and displayed — verified again after a
  force-stop and relaunch.

**Not tested:**

- **No physical device, no OEM ROM validation.** Everything above ran on
  emulators. Real LINE / Messenger / Threads behaviour on real hardware is
  still unverified.

This build must not be described as *Stable*.

## Known issues

See the "已知問題" section of `README.zh-TW.md` for the maintained list. The
ones that matter most for a release decision:

1. Debug-signed and `debuggable` — not suitable for sensitive data.
2. No in-place upgrade path to a future production-signed build (data loss on
   switch).
3. DHC export exists, but there is **no in-app restore**.
4. Image capture is **off by default**; when enabled, image decode/encode still
   runs on the notification callback (main) thread, so heavy image traffic can
   cause perceptible latency.
5. A few notifications **without a timestamp may be captured more than once**.
6. When rows cannot be decrypted, pagination has a known limitation: skipped
   rows can make a page show fewer items than expected.
7. No physical-device / OEM validation.

## Installing

```bash
adb install PrivateInboxClassic-v0.4.6-alpha-debug.apk
```

To update an existing **v0.4.4-alpha** install without losing data:

```bash
adb install -r PrivateInboxClassic-v0.4.6-alpha-debug.apk
```

This only works because both are signed with the same certificate. Verify before
installing:

```bash
apksigner verify --print-certs PrivateInboxClassic-v0.4.6-alpha-debug.apk
# expect: c876051e2879d005abf610277e58f40b728c62cac36a7748f3357200af3377a4
```

If the certificate differs, **stop** — `adb install -r` will fail, and forcing
it means uninstalling and losing data.
