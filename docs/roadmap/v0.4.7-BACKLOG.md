# v0.4.7 Backlog

Features deferred from v0.4.6 (scope frozen for Alpha).

## Persistent Intake Journal
Durable write-ahead log so capture survives process death between capture and commit. Currently DESIGN_ONLY — in-memory batches are lost on process death.

## Portable Archive Import
Import DHC-encrypted archives from other devices/installations.

## LINE Media Preview Reliability
Image decode failures currently drop the photo but keep the text row. Improve retry/decode reliability for LINE media URIs.

## True OEM Device Matrix
Emulator-only (API 36) for v0.4.6. Need real devices with LINE, Telegram, WhatsApp, Instagram, Messenger, Threads.

## Cross-Device Sync / DHC Expansion
DHC v0.2 offline export exists. Sync across devices requires a transport (not yet designed; no INTERNET permission — would need careful threat model).

## Rust Core Feasibility
Evaluate moving the SQLite/crypto core to Rust for safety and portability.

## Deferred Claude review findings (v0.4.6 → v0.4.7)

These are the specific findings carried over from the v0.4.6 independent review.
Each is referenced by ID from
`docs/verification/v0.4.6/CLAUDE-FINDING-RESOLUTION-MATRIX.md`.

### F-02 — P2 — Image work on the notification callback thread
Image scaling/JPEG encoding and serialized media reads still run on the main
thread inside the notification callback. Move decode/encode to the worker; keep
only the URI read synchronous (the grant can be revoked).

### F-03 — P2 — Duplicate rows for timestamp-less messages
When the source provides no timestamp, a window shift can store the same message
twice. Fixing this means changing the dedup discriminator, which would change the
identity of already-stored rows — needs a migration design, not a patch.

### F-04 — P2 — Pagination can stop early or stay stuck
A page containing an undecryptable row, or an empty page, can leave the "load
older" affordance in a wrong state. Needs an explicit page-status model.

### F-09 — P3 — Merge/unmerge latent atomicity
Merge/unmerge is not wired to the UI in v0.4.6. Latent TOCTOU and merged-away
target handling should be fixed before it is ever exposed.

### F-10 — P3 — CI masks a release-build failure
`.github/workflows/android.yml` runs `:app:assembleProdRelease || echo "..."`,
so a genuine release-build failure is swallowed. Remove the `|| echo` once a
release keystore exists.

### F-11 — P3 — UI-test effectiveness
Instrumentation forces `unlocked` via reflection, so the real credential gate is
never exercised. Add a real lock-screen / failure-injection test.

### F-12 — P3 — `existingIdForFingerprint` never matches
It binds `String(fingerprint)` against a BLOB column, so it never returns the
existing row id and callers fall back to `DUPLICATE(-1)`. The row is still not
duplicated (UNIQUE holds), but the reported id is wrong.

### F-13 — P3 — Settings shows the wrong version
`MainActivity.kt` renders `v0.3.1（內部測試）`. Should read the real version from
`BuildConfig.VERSION_NAME`.

### D-06 — P3 — Release script cannot verify the certificate
`scripts/release/verify-artifact.sh` prints the certificate but has no
expected-cert parameter, so a wrong-certificate APK passes. Add
`--expected-cert <sha256>` and fail on mismatch.

### D-07 — P3 — Connected-test XML is not published
CI uploads JVM HTML only. Upload
`app/build/outputs/androidTest-results/connected/**` so the instrumentation
result can be audited per test from artifacts.
