# v0.4.7 — OriginOS Listener Reliability: Root Cause Analysis

**Status:** investigation + diagnostic fix complete; **real-device verification PENDING**

## Reported symptom

vivo X200 Pro / OriginOS, Private Inbox Classic v0.4.6-alpha:

```
received=10716  parse_success=1128  db_writes=1017  failures=3
listener_permission_granted=true
listener_status=PERMISSION_GRANTED_NOT_CONNECTED
LISTENER_DISCONNECTED: multiple   LISTENER_CONNECTED: observed
ACTIVE_RECOVERED: count=2
```

Intermittent missed notifications while the app was backgrounded.

## What the evidence does NOT prove

- **`PERMISSION_GRANTED_NOT_CONNECTED` is not proof the process died.** It only
  says "access is granted but this process holds no live bind". A fresh process,
  a system that has not rebound yet, and a killed process all produce it.
- **`ACTIVE_RECOVERED count=2` does not prove two messages were stored.** It
  counts notifications handed to the pipeline at connect time; dedup may drop
  them, and a DB failure would not be visible in that number.
- The old `listenerConnected` was an in-memory flag. After a process restart the
  UI could read a stale `CONNECTED` left in SharedPreferences by the dead
  process, so the displayed state and reality could disagree in **either**
  direction.

## Defects found in v0.4.6 diagnostics (confirmed by code reading)

| # | Defect | Consequence |
|---|---|---|
| D1 | Export hard-coded `"version": "0.4.0-alpha"` | Every report was mislabelled; version could not be trusted |
| D2 | Settings screen hard-coded `v0.3.1` | User saw the wrong version |
| D3 | No process session id | "Process restarted" was indistinguishable from "never connected" |
| D4 | No listener instance id | Two consecutive binds could not be told apart |
| D5 | `onDestroy` recorded nothing | On OriginOS a destroy without a clean disconnect left the flag set |
| D6 | Persisted CONNECTED evidence had no expiry | A days-old flag read as current connectivity |
| D7 | `rebind()` did not record its own outcome | The caller had to guess; MainActivity fabricated a `LISTENER_DISCONNECTED` on refusal |
| D8 | No rebind rate limit | An automatic caller could storm the system |
| D9 | `PERMISSION_GRANTED_NOT_CONNECTED` unexplained in UI | User could not tell whether action was needed |

## What was fixed (this PR)

- D1/D2: `BuildConfig.VERSION_NAME` / `VERSION_CODE` used everywhere; `buildConfig` enabled.
- D3: `process_session_id`, `process_start_ts`, monotonic `process_start_count`, plus a
  `PROCESS_STARTED` event per process.
- D4: per-bind `listener_instance_id` with a monotonic counter.
- D5: `LISTENER_DESTROYED` recorded in `onDestroy` before teardown.
- D6: 30-minute `CONNECTION_EVIDENCE_TTL_MS`; older evidence → `CONNECTION_EVIDENCE_STALE`.
- D7: `REBIND_REQUESTED` / `REBIND_ACCEPTED` / `REBIND_REFUSED` recorded inside `rebind()`;
  MainActivity no longer records a fabricated disconnect.
- D8: `REBIND_COOLDOWN_MS` = 60 s for automatic callers; user taps bypass it.
- D9: settings screen explains the state and lists the OriginOS battery/autostart
  settings the user must change (the app cannot change them).

Export schema 2 → 3.

## Hypothesis (NOT yet confirmed)

The most likely explanation is **OriginOS background-process management severing
the listener bind**, with the app unable to distinguish that from other causes
because of D3–D6. The diagnostic fixes make the next field report decisive:

- If `process_start_count` climbs while `received` does not, the process is being
  killed and restarted.
- If `process_start_count` is flat but `listener_connected_in_process` is false
  with a recent `disconnected_ts`, the bind was severed while the process lived.
- If `LISTENER_DESTROYED` appears with `was_connected`, the service was torn down
  without a clean disconnect — the OriginOS signature.
- `CONNECTION_EVIDENCE_STALE` appearing after a long background period is direct
  evidence that the old evidence was not current.

**This hypothesis is not confirmed until a v0.4.7 diagnostic is captured on the
device.**

## Not changed

Dedup, database schema, encryption, capture policy, notification parsing and the
whitelist are untouched. No INTERNET, no new permissions, no foreground service,
no polling loop, no Accessibility.
